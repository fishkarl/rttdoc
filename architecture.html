Agora Real-time Translation Architecture Documentation

Overview

This document describes how to implement real-time voice translation functionality based on the Agora SDK. This feature allows users speaking different languages to communicate without barriers, as the system automatically detects the user's language and translates voice content into the target language displayed as subtitles.

Prerequisites

  • Registered Agora developer account
  • Created Agora project and obtained App ID
  • Integrated Agora RTC and RTM SDK into your application
  • Turn on Agora STT service from Agora console

System Architecture

The system consists of the following main components:

  • User Client: Application with integrated Agora SDK
  • Demo Server: Handles authentication and token generation
  • RTC: Agora Real-time Communication service, responsible for audio stream transmission
  • RTM: Agora Real-time Messaging service, responsible for messages and translation results transmission
  • Agent: Translation agent, responsible for speech recognition and translation processing

Workflow

1. Initialization Process

User Client → Demo Server: Request token (with uid)
Demo Server → User Client: Return token

When the application starts, the client needs to request tokens for RTC and RTM connections from the server.

2. Login Process

User Client → RTC: Login to RTC using token, enable stream message monitoring
User Client → RTM: Login to RTM using token

Use the tokens obtained from the server to log in to both RTC and RTM services.

3. Language Synchronization and Agent Startup

RTC → User Client: Get remote users' source languages, deduplicate and set as local target languages
User Client → RTC: Call Join API (configure local language settings and enable STT service)
RTC → Agent: Call Join API (forward language settings)
Agent → User Client: Start worker process to subscribe to application audio streams and enable translation
RTC → User Client: Startup successful
User Client → RTM: Synchronize local language settings to RTM user status

At this stage, the system detects user languages, configures speech recognition and translation services, and synchronizes language settings.

4. Remote User Status Change Handling

RTC → User Client: Remote user join/status change notification
RTC → User Client: Get remote users' source languages, deduplicate and set as local target languages
User Client → RTC: Call Update API (update target language settings)
RTC → Agent: Call Update API (update language configuration)
Agent → User Client: Update worker process language settings from previous agent startup process
RTC → User Client: Update successful

When new users join or existing users' status changes, the system re-detects languages and updates translation configurations.

5. Real-time Translation Process

User Client → RTC: Listen for stream messages
RTC → Agent: Push translation results to channel-wide stream messages
Agent → User Client: Receive stream messages and display subtitles

This is the actual translation workflow where users' speech is recognized, translated, and then displayed as subtitles to other users.

API Interface Description

Initialization and Authentication

Request Token API

  • Function: Obtain tokens for RTC and RTM connections
  • Parameters: User ID (uid)
  • Returns: Authorization token

Agent Related Interfaces

Join API

  • Function: Forward language settings to translation agent
  • Parameters: Language configuration information

Update API

  • Function: Update language configuration
  • Parameters: Updated language configuration

Leave API

  • Function: Let worker leave channel and stop transcription and translation
  • Parameters: None

Subscription Relationship Model

Figure 3: Subscription Relationship Between Components

The diagram above illustrates the subscription relationship between different components in the Agora real-time translation system:

  • User Clients: Each user client subscribes to audio streams from other clients and translation results from the Agent.
  • Translation Agent: Each Agent subscribes to specific audio stream which in the channel to perform speech recognition and translation.
  • Data Flow: Audio streams flow through RTC while translation results are distributed via RTM to ensure efficient delivery.
  • Scalability: This architecture allows for seamless scaling as more users join the channel, with the Agent handling the increased translation load.

This subscription model ensures that each component receives only the data it needs to process, optimizing bandwidth usage and system performance. The Agent acts as a central translation hub, while keeping the communication paths between users direct and efficient.

TIPS

We recommend assigning a dedicated worker for each end user to better recognize and translate conversations. Each worker should only recognize one language. You can configure this using the following field:

"uidLanguagesConfig": [                        // Optional: Configure specific languages for individual users
     {
        "uid": "<YouSpecifyUid>",              // User ID to configure language for
        "languages": ["<YourTranscribeLanguages>"] // Languages to use for this specific user
     }
  ]

Here's a complete example of an actual request:

{
  "name": "**",
  "languages": ["en-US"],
  "maxIdleTime": 30,
  "rtcConfig": {
    "channelName": "22",
    "subBotUid": "*",
    "pubBotUid": "****",
    "subscribeAudioUids": ["144757"],
    "subBotToken": "*****",
    "pubBotToken": "*****"
  },
  "uidLanguagesConfig": [
    {
      "uid": "*",
      "languages": ["en-US"]
    }
  ],
  "translateConfig": {
    "languages": [
      {
        "source": "en-US",
        "target": ["zh-CN"]
      }
    ]
  }
}

In this example, we've configured a dedicated worker to recognize English (en-US) for a specific user, and translate it to Chinese (zh-CN).

Important Notes

  • Ensure sufficient permissions to access user microphones
  • We suggest to use dedicated worker for each user, so users can speak simultaneously
  • Demo server play a manager role, it should control worker life cycle.
